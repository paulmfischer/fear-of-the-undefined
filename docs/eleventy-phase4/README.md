# Phase 4 — Styled blog and publishing features

The Eleventy preview is ready for the planned user testing pass. Production, CI, and the legacy Lume setup remain unchanged. Output is still isolated in `_site-eleventy`.

## Preview and review

```sh
nvm use
npm ci
npm run serve
```

Open http://localhost:8080/ and compare with https://paulmfischer.dev. Check desktop/mobile layouts, both themes, navigation, search, article formatting/images/code blocks, and About. The explicit missing-page document is at `/404.html`. Feed endpoints are `/posts.rss` and `/posts.json`; sitemap and robots are `/sitemap.xml` and `/robots.txt`.

The local preview was left running for the phase 4 review. Restart it with the command above if the session has ended. Ctrl+C stops it.

## Restored features

- Tailwind **4.1.13**, preserving the baseline release, with PostCSS and Lightning CSS compilation/minification. The existing CSS source is reused without editing it. CSS is generated from the final rendered class names so Markdown attributes and computed TSX classes are included.
- Highlight.js code coloring, including C# and the existing highlight stylesheet.
- Inline Tabler SVG icons, with no browser-side React runtime.
- Reading-time labels matching all nine live baseline values: 4, 2, 4, 3, 4, 2, 3, 2, 3 minutes in homepage order. Word segmentation uses `Intl.Segmenter`, 275 words/minute, and the full Markdown source to preserve those estimates.
- Avatar-derived 32px ICO and 180px Apple touch icon; existing SVG favicon retained.
- Pagefind default search UI and a fresh index of articles and About. Repeated navigation, the homepage listing, 404, and standalone Todo demo are excluded from indexing.
- RSS and JSON feeds with the latest ten articles (currently nine), stable article IDs, publication dates, and absolute links/image URLs in feed content.
- Sitemap for the same eleven content URLs as the baseline, plus robots output advertising it.
- Existing images, browser scripts, résumé, and Todo demo remain copied unchanged.

The build generates favicons, renders HTML, compiles styles and publishing outputs, then builds the search index. Every full/watch build refreshes publishing output. CSS, the highlight stylesheet, templates, helpers, and data files participate in development watching.

## Verification

- Clean `npm ci`: passed; npm reported zero vulnerabilities.
- `npm test`: all eight regression groups passed, covering routes/content compatibility plus feeds, dates, highlighted code, reading times, SVGs, compiled CSS, icons, sitemap, robots, and search assets.
- `npm run type-check`: passed. `skipLibCheck` skips conflicting third-party DOM declarations from LinkeDOM; application TS/TSX remains checked in strict mode.
- Live comparison found no missing non-text public resources. All nine feed IDs match production, including the encoded bracket characters in the Actions article. Publication instants match; the new JSON feed expresses them as ISO timestamps rather than the old RFC-formatted strings.
- Desktop/mobile browser checks passed for themes and persistence, sidebar opening/closing, article search, highlighting, and publishing endpoints. No page exceptions or failed-resource responses were observed in that smoke pass.
- Search queries for `automapper` and `photoprism` returned the article and About respectively. Pagefind may use partial/fuzzy term matching; a removed synthetic token query matched the Actions article's real token-related text, rather than retaining the temporary article.
- Temporary CSS and article-title edits verified stylesheet, feed, and search rebuilding. Both source files were restored byte-for-byte afterward.
- Desktop typography matched live computed font family, size, weight, and line height. About list indentation/style matched after correcting rendered-class scanning. Eight representative screenshots were visually inspected against the phase 1 baseline.

## Known differences and phase 5 scope

- Text versions remain deferred; generated Text Version links are absent. Historical links inside unchanged article prose may still refer to old `.txt` URLs. Their deployment handling remains a phase 5 gate.
- The existing mobile header/content overlap and narrow-screen footer overflow are reproduced from the baseline. They were not redesigned during the generator migration.
- The footer credits Eleventy. Feed generator metadata and timestamp formatting change; article identity and publication instants are preserved. Sitemap omits volatile modification timestamps rather than inventing new dates on every build.
- Search/feed/favicons are functionally restored; generated bytes and search-index filenames need not match Lume. Images are served as files instead of Lume's inline data URLs.
- This phase is the user review checkpoint. Phase 5 still covers feedback, comprehensive final verification, clean/delete rebuild behavior, CI/documentation cleanup, text-URL handling, and preparation for deployment. Nothing has been published.
